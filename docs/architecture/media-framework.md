# Jamak architecture

Jamak ships one Manifest V3 desktop Chrome extension from `apps/chrome`. The former Python server, macOS companion and legacy `extension/` application are removed. iPhone Safari and a macOS desktop app are roadmap items only.

## Runtime and data flow

1. The popup defaults to manual English, allows English/Japanese/Korean selection and offers an optional automatic-detection checkbox. Selecting a source language disables detection. The subtitle language is independently selectable as Korean, English or Japanese; same-language speech skips translation. Manual Korean uses fixed-language Whisper. It prepares models and starts/stops capture for its original tab.
2. The service worker coordinates session state and action-granted tab access. It owns the control channel, not inference.
3. An offscreen document keeps tab capture, audible playback and inference alive after the popup closes.
4. `packages/media-web` and the audio worklet provide ordered PCM with capture-relative timing. Tab capture includes iframe and Web Audio output; it does not isolate one video or capture microphones/system audio.
5. `packages/engines-browser` normalizes input, recognizes speech, translates text to the selected subtitle language and independently estimates speakers. Source and translation revisions share session, epoch and utterance identity.
6. `packages/core` reconciles revisions and schedules presentation. The page content script renders subtitles through `packages/presentation-web`; a separate window shows original/translation history.

Navigation, target loss and Stop invalidate the session and release resources. Stale worker replies or acknowledgements must not revive captions. The offscreen preparation snapshot carries the current stage’s numeric download fraction to one popup progress bar. Reopening restores it; loading or browser-owned stages without a reported fraction are indeterminate. Ready, failure and Stop hide the bar. The snapshot also carries the actual selected model list for the popup’s compact model-information table; before preparation, the table shows the expected configuration for the selected mode. The preparation button uses neutral preparation text; actual downloading and cached-model loading use their background stage descriptions. Raw model IDs, pinned revision hashes and byte-count diagnostics are not rendered in the popup. Model preparation persists independently of the popup; cancellation and disposal must release workers and pending jobs.

## Caption and speaker invariants

- Never pair a translation with a different source revision or epoch.
- Preserve the previous translation while its correction is pending.
- Keep every provisional row in its original stack position until its latest source and matching translation are final, regardless of newer captions. Pending corrections block retirement of the displayed previous pair even when that pair was final. Receipt of the corrected final pair grants at least four seconds of final reading time, including unchanged text; long provisional rows still advance their measured parts.
- Recognition can withdraw a removed provisional hypothesis with a newer final, empty source revision marked `retracted`. This removes its overlay/history row immediately without translation or reading time. The revision store retains a bounded tombstone to reject late source, translation and speaker replies; confirmed sentences cannot be withdrawn. Background snapshots omit withdrawn rows, and open history windows receive the removal event.
- Do not discard unread captions or replay a retired sentence when final recognition arrives in a burst.
- Keep visible reading progress separate from transcript storage. Only visible text counts toward reading time. Completed generation paints immediately even for a provisional source so a queued draft cannot be lost when the next source becomes pending. The live view retains an existing translated sentence during regeneration for a newer same-language source. It admits an incomplete replacement only when it extends that sentence verbatim, otherwise waits for generation completion. Initial translation, language changes and same-language bypass remain immediate. Rendering replaces the differing range within the existing text node; two-line offsets reconcile against the last actually displayed text so held prefixes cannot rewind reading. History retains the canonical exact-revision output, independently of this live display hold.
- Ready captions appear below earlier captions in a bounded stack. Visible rows accrue reading time concurrently and long rows advance their own measured two-line parts. Completed rows retire oldest first after 4–6 seconds per visible part and a 250 ms fade; a newer row retains its original reading deadline when older rows leave. Clipped rows wait without spending reading time, and one row’s fade never fades the whole stack.
- Speaker inference runs independently of text presentation. Stable session-local IDs select background colors; no “speaker 1” labels are rendered.
- Very short or uncertain speech can remain unassigned. Speaker numbers are anonymous clusters, not personal identity.

The page overlay stays attached to the document root. During Fullscreen API playback it uses a manual popover to enter the browser's top layer above fullscreen video, player or iframe surfaces; normal `z-index` cannot place a page overlay above that layer. Leaving fullscreen removes the popover state and restores normal positioning without recreating the view or presentation policy. Its transparent background/backdrop and `pointer-events:none` preserve playback controls and avoid focus-taking UI. Stop/disposal removes the surface, including an open fullscreen popover.

Whisper timestamps describe acoustic segments, which can contain part of a sentence or several sentences. Join unfinished pieces before publishing. At the 12-second snapshot limit, retain an incomplete trailing phrase's PCM when a complete preceding segment can be trimmed; drain at EOF, an automatic-mode speech boundary or a settled pause, with a bounded flush when no usable boundary exists. A punctuation correction inside retained audio must not repeat a committed prefix. Chrome Japanese translation splits ASCII/full-width sentence punctuation, polite questions and conversational endings (including polite よ/ね) before a new-script word or discourse marker such as `まったく`/`ちょうど`, preserving word-internal text such as `よく`, relative verbs such as `行った駅` and quoted questions followed by `と`/`を`. Each phrase is translated separately and joined into one exact source-revision pair; native translation can otherwise return only the first clause of an unpunctuated input.

Whisper normally re-decodes after roughly one second of new PCM and publishes the uncommitted text as a provisional transcript. Subsequent snapshots revise that caption with the same utterance ID and increasing source revisions, including language corrections in automatic mode. Consecutive matching results confirm completed sentences; EOF, a completed automatic speech boundary, settled pauses and the existing bounded-window policy can also finalize text. The confirmed leading sentence finalizes the current caption, and its unfinished successor becomes the next provisional caption. PCM trimming retains that successor's caption identity. Unchanged drafts produce no extra revisions; queued replacements of the same caption coalesce without dropping final sentences. Translation queues preserve exact source pairing and bypass translation when speech matches the selected target. Streaming translators pin their active published source while validating and coalescing incoming recognition corrections; complete-result translators still reject superseded-source results. This is application-level streaming around the selected Whisper model; accumulation and model execution still determine initial latency.

If a snapshot removes the unfinished successor or returns no uncommitted text, withdraw its draft and release its identity before trimming or starting the next turn. A final empty/filler-only correction in the translation queue likewise withdraws a previously accepted provisional source rather than silently filtering its finalization. Queued translations are removed and in-flight replies are rejected by exact revision/withdrawal checks. An orphaned provisional head must not block the retirement of every later completed row.

## Image translation

The popup exposes Audio/Image tabs. Image mode chooses a ko/en/ja target and discovers all displayed main-document `<img>` elements or lets the user click one. `image-background.ts` brokers action-granted scripting/capture, session metadata and local text-language detection; `image-runtime.ts` is imported by the existing shared offscreen document and owns OCR/translation/results independently of audio. No editor tab/window or second offscreen document is created. Closing the popup leaves processing alive. A runtime snapshot restores image session state when the service worker restarts. Tokens, pinned document IDs and paint revisions reject obsolete work.

`tab-image.js` leaves original images intact, reading origin-clean pixels with a 2560px longest-side limit. Tainted/cropped/letterboxed images use a visible-tab screenshot, temporarily hiding Jamak’s image surfaces and cropping in the offscreen document. The uncropped screenshot is transient. Only the visible portion is available; occlusion can affect it. The original tab must remain active for screenshot capture. Automatic processing restores the initial scroll position. Discovery excludes CSS backgrounds, iframe images and later additions.

The offscreen runtime downloads the selected pinned detection/recognition archive pair: PP-OCRv5 Mobile (21,544,960 bytes), PP-OCRv6 Small (31,211,520 bytes) or PP-OCRv6 Medium (138,762,240 bytes), validating SHA-256 and size on downloads/cache reads. `image-sandbox.html` receives pixels and model buffers through MessageChannel. Only this opaque-origin, permissionless sandbox allows OpenCV’s dynamic bindings; it has no parent DOM access or external network allowance. Bundled ONNX Runtime 1.30 WASM runs one thread. White padding/alpha compositing are analysis-only, with coordinates mapped back to the original. The sandbox is removed after each image/cancellation. The normal extension CSP adds only the official archive endpoint; the narrowly scoped host permission handles that endpoint’s missing CORS headers. No runtime code is downloaded.

The service worker uses `chrome.i18n.detectLanguage` per OCR line, with reliable same-image context for compatible short lines. Supported detected languages are en/ja/ko; uncertain or reliably unsupported languages remain unknown. No additional text-decision model or audio detector runs. The native/model translator receives each actual source→selected-target pair; matching-language regions reuse the original without inference. Native auto-pair preparation starts from the explicit popup action before OCR to preserve first-use user activation. Hy-MT2 loads lazily for the first differing pair. Idle hosts reuse main’s translator preparation API; cache identity is independent of target. Model/output options are frozen per session and shared settings are preserved.

Results and compressed source pixels remain in runtime memory; weights and language/model preferences alone persist. Shadow-DOM labels follow image resize/scroll/load and support drag/keyboard movement. Each image owns a themed download/visibility dock and a native auto-popover editor in the browser top layer, so later image controls cannot cover it. Positioning uses the visual viewport, with edge clamping/flipping, a bounded scrolling body and resize observation of both image and editor. The shared native `jamak-select` CSS is bundled into the shadow root. In-progress/error notices sit at the lower-left below image controls. Successful ready state removes the page notice, including unknown-language summaries, while details remain in the extension popup. Caption labels intentionally have no focus ring; buttons and form fields retain it. One measured layout drives labels and PNG export, whose margins expand for moved labels. The runtime retains an immutable origin per OCR region; a reset command restores x/y, clears manual placement and publishes a new fenced paint. Return icons are UI only, and resetting also restores export geometry without OCR or translation. Explicit Stop releases inference but retains completed results for movement/direct translation edits/export; source retranslation requires a new analysis. Only the adjacent pencil opens editing for its OCR region. Caption clicks and keyboard movement never open editing. Five native radio cards with growing Aa samples and a check marker in the extension popup’s Image tab set a job-wide font scale to 0.7/0.85/1/1.25/1.5 (default 1), through a trusted-popup, tab-matched size command without OCR/translation. The preference and OCR selection persist separately in `jamak-image-options-v1`. The shared layout uses 70% of the OCR-derived base as normal, matching the former very-small preset, then applies the saved relative scale before rounding, wrapping and overflow fitting. Page and PNG share this smaller baseline; saved preset values retain their identities. The current scale remains in session metadata and can repaint all retained results after Stop; text drafts and original-position reset stay independent. Regions without a translation retain adjacent edit actions over the source, without adding fallback text to PNG exports. Region fields remain mounted when switching captions so drafts survive. The image dock contains only download and caption-visibility actions. The dock starts at the upper-right and can be dragged inside the image or into a 24px margin. Its normalized image-relative placement survives paints and scrolling; viewport clamping does not rewrite saved placement. Editor headers/grips drag a viewport-clamped floating window independently of the image. The two fixed active/inactive image levels keep a moved caption’s reset action above other images, while editors remain in the browser top layer. Editor controls remain mounted while label content updates, preserving open state, focus, scroll and other unsaved fields. Applied changes accept the actual regenerated output. Outside clicks, including caption dragging, dismiss the editor. Its close button or Escape while focused dismisses it and returns focus; native select Escape still closes only its picker. The native auto-popover allows one image editor at a time; another pencil dismisses the previous one. Dismissal/reopening retains fields and moved placement. Source replacement/removal/navigation clears the surface and its top-layer editor. New analysis/navigation/tab closure disposes earlier results. Image controls never start/stop audio. See [research, licenses and verification](../verification/image-translation.md).

## Local development

Local development uses `scripts/dev-chrome.mjs`: a Vite build watcher writes only `.ralph/dev/extension`, a loopback fixture server owns port 8790, and an owned Chrome for Testing profile loads the extension. The browser's official local components reuse the existing harness cache; extension settings/model caches remain in the dev profile. This adds no shipping runtime or external service. Shutdown closes only these owned resources and keeps cached models; extension reload after rebuild is manual.

Custom launch arguments bypass Playwright's default startup-page wait. The launcher explicitly waits for Chrome's initial blank page before navigating it, then closes other restored pages in its own context. Startup leaves one conversation tab/window and does not open extension management automatically. The launcher owns SIGINT/SIGTERM cleanup to avoid racing Playwright's process-exit handlers.

## Models

With Chrome defaults, manual English and Japanese share Chrome's on-device streaming path. Interim results publish after a 180 ms coalescing gate; native finals bypass it. Native results can accumulate several turns before reporting final. A span closed by the existing measured audio pause finalizes when its previously published text is unchanged in a subsequent result; the last open span stays provisional. Later native corrections retain the span ID and increase its revision. The existing revision pipeline shows drafts before translation and preserves paired translations while corrections are pending. WebGPU availability does not override a supported native speech API. Unsupported native speech uses the Whisper fallback.

| Task | Runtime/model | Conditions |
| --- | --- | --- |
| Recognition | Chrome SODA, local SpeechRecognition | Preferred for manual English/Japanese; required local API and language packs |
| Recognition | Whisper large-v3-turbo FP16 through Transformers.js/ONNX | Default automatic/Korean modes and native fallback; WebGPU required; ~1.6 GB speech model |
| Recognition choices | Small FP16; Large v3 Turbo FP16 | Advanced overrides native recognition. FP16 uses WebGPU. All supported choices support manual and automatic languages and use Silero VAD. |
| Voice activity for fallback | Silero VAD | Bundled ONNX runtime; pinned artifact |
| Translation | Chrome TranslateKit | Default local Translator API and packs for all directed English/Japanese/Korean pairs |
| Translation choices | Hy-MT2 1.8B q4f16 (~1.38 GB) | Hy-MT2 uses WebGPU/FP16 and generated-text streaming. One resident multilingual model, all directed English/Japanese/Korean pairs |
| Language detection choice | One-pass VoxLingua107 ECAPA FP32 (~87 MB) | Optional CPU/WASM audio classifier before fixed-language recognition; default shares the recognition encoder instead |
| Speaker embeddings | WeSpeaker VoxCeleb ResNet34-LM q8 | Local WASM worker; ~6.7 MB first download; Advanced can disable it |

The pinned artifact inventory, sizes and hashes lives in `packages/engines-browser/model.ts` and `translation-model.ts`. The separate Advanced window offers registered choices through independent recognition, translation, language-detection, speaker and image OCR selectors. Each change stops/disposes the old session, forwards the original source/tab plus selected options to offscreen preparation, and downloads missing artifacts immediately. It can be opened from the popup or Chrome extension options; without an original tab it prepares models only, and the action popup binds a tab on subsequent preparation. No selection starts capture.

The popup language field and Advanced model fields use the local `jamak-select` CSS component. Chrome's customizable native select/picker styles the dropdown alongside its trigger; labels, descriptions, value/change events and disabled behavior stay native. Norux semantic roles alias Jamak's existing light/dark colors and system font, preserving the product appearance without a framework or global design migration. Older implementations retain a styled native control. The popup width is bounded by the available viewport for zoom/narrow reflow.

Settings use extension-origin localStorage (`jamak-model-options-v1`), shared by the visible extension pages without adding storage permission. Prepared snapshots carry immutable recognition/translation/detection/speaker options, subtitle language and the OCR choice for combined Advanced preparation. Popup readiness checks the corresponding model caches and native packs, and start remains disabled when settings do not match the prepared configuration. Closing Advanced preserves preparation; reopening only observes status. Changing an Advanced model choice or Stop terminates model workers and their pending downloads, retaining completed cached files. Before capture starts, the popup sends language-only changes through `prepare` without Stop when model choices match. Offscreen replaces the immutable language snapshot and reconfigures its ready engine, retaining loaded Whisper/VAD, translation, speaker and detector workers. Entering automatic mode or switching from SODA to Whisper prepares only newly needed components. Native translator instances are keyed by their actual source/target pair and reused on return. Once a pipeline exists, language reconfiguration is rejected; Stop still releases every retained resource. Chrome owns its native pack downloads and may continue them independently after application preparation stops. Native defaults still use Turbo for automatic/Korean or unsupported SODA; explicit selections never silently fall back. Speech already in the subtitle language bypasses every translator.

Advanced saves a new selection before requesting preparation, retaining it even when preparation fails. The popup ignores old model metadata/readiness when options differ; missing snapshot options identify Chrome defaults only. Advanced independently probes Chrome speech/translation pack availability or all registered cache responses and exact Content-Length values for each selected model. Partial, truncated or evicted cache files are not complete; labels are derived again on background events and reopening, without initiating downloads. Matching source/subtitle languages label translation as unused. Saved files and loaded-model readiness remain distinct, and the current stage's progress is determinate only when the background reports a fraction.

Advanced coalesces overlapping inventory scans and reads only exact Content-Length metadata, releasing unused cache-response streams without reading model bodies. A progress update must not allocate another OCR weight buffer in the settings renderer. The runtime still validates full bytes and SHA-256; verified legacy OCR cache entries acquire exact length metadata, and streamed downloads are hashed directly without a Response/ArrayBuffer copy. Any unified-stage failure closes the partially prepared engine and loaded workers before publishing the failed snapshot, preserving selected options and verified files for retry. Stale cleanup cannot overwrite a newer preparation's state. Audio-only preparation after idle/failure omits the old OCR readiness metadata; only reconfiguring an already-ready engine retains it.


Successful Advanced preparation emits one `models-ready` event from offscreen only after audio/translation preparation and OCR download/verification both finish and its generation is still current. The service worker accepts only the owned offscreen sender and creates a local desktop notification through `chrome.notifications` (declared `notifications` permission), independent of the visible windows. Stop, failed/stale preparations and ordinary popup cache preparation do not emit this event. Notification rejection does not change readiness. OS/Chrome notification settings can prevent visible delivery; notification content contains no transcript. [Chrome notification API](https://developer.chrome.com/docs/extensions/reference/api/notifications).

The bounded translation worker receives only transcript text, executes the pinned ONNX model from prepared Cache Storage, and returns exact source/session revision pairing. Hy-MT2 uses a text-generation pipeline with an upstream-style target-language translation prompt naming the detected source and selected subtitle language and deterministic decoding on WebGPU/q4f16. Its pinned conversion embeds weights in one ONNX file, so loading explicitly disables inherited external-data requests. The internal NLLB/M2M100 audit candidates retain their translation pipeline on WASM/q8. WebGPU/FP16 support is checked before downloading Hy-MT2; failure stays visible. NLLB uses Flores language codes; M2M100 uses ISO codes. All share the existing serial translation/revision queue and terminate on cancellation. Hy-MT2 emits cumulative text through TextStreamer; the host keeps only the latest pending chunk. Chrome TranslateKit consumes its ReadableStream with abortable readers when available, preserving Japanese phrase splitting and joining; implementations without streaming use translate(). Intermediate translation revisions are never final, even for a finalized source. Completion emits a separate final translation revision, independent of recognition finality; caption retirement still requires both finals. A final source confirmation with identical text and language reuses that complete translation with the new source revision, including confirmations queued while generation is active. Text changes still invoke the translator. A new source correction resets translation completion while retaining the revision watermark; finalized translations cannot regress within the same source revision. For a streaming translator, separate bounded revision stores track the latest validated recognition input and the published source. The active source stays published while its translation stream paints; newer same-language corrections coalesce for the next job instead of making every generated chunk stale. This can delay visible original corrections by an active inference. Language corrections and same-language bypass publish immediately and reject old-language chunks. Complete-result translators retain immediate source publication and obsolete-result rejection. The queue assigns one published translation sequence across generated chunks and same-language bypass, validating increasing producer revisions within each stream. The overlay uses its existing 180 ms correction cadence and retains the previous displayed pair until a matching translation arrives. Model comparisons need real inference checks; successful downloads or mocked selectors are insufficient. Model downloads use the manifest's allowed Hugging Face endpoints; inference does not send audio or embeddings to a server. Chrome manages its own language packs. Availability is device/browser dependent; first downloads need internet.

VoxLingua107 ECAPA-TDNN weights and the registered [ONNX export](https://huggingface.co/christopherthompson81/voxlingua107-lid-onnx) are Apache-2.0, with SpeechBrain/VoxLingua107 and exporter attribution retained. WeSpeaker weights are CC-BY-4.0; see [attribution](../verification/captions/conversation-speakers.md). The upstream [Whisper weights](https://huggingface.co/openai/whisper-large-v3-turbo) and [Silero VAD](https://github.com/snakers4/silero-vad) are MIT-licensed. [NLLB](https://huggingface.co/facebook/nllb-200-distilled-600M) weights are CC-BY-NC-4.0, intended for research/noncommercial use, and retained only in the audit registry. [M2M100](https://huggingface.co/facebook/m2m100_418M) weights are MIT. The pinned [NLLB ONNX](https://huggingface.co/Xenova/nllb-200-distilled-600M) and [M2M100 ONNX](https://huggingface.co/Xenova/m2m100_418M) conversions retain upstream attribution. Model licenses remain separate from the application license. Consult each registered upstream model card before redistributing weights.

## Automatic language routing

`auto` belongs to session settings; transcript and translation revisions carry the actual utterance language. Automatic mode uses the selected multilingual Whisper weights, not a text decision model or additional language-ID download. The pinned Transformers.js 4.3.0 implementation defaults to English when language is omitted, so the ASR worker explicitly decodes the first language token, calculates probabilities across the model's language tokens, and chooses between `en`, `ja` and `ko`. It then transcribes using the same encoder output. Its pinned SDK adapter admits `encoder_outputs` into the model's forward parameters; verify real model execution when upgrading the SDK.

Recent confident language is a session-local tie breaker only when acoustic scores differ by less than 0.05. Clear new evidence can switch immediately. These raw model probabilities are not calibrated accuracy guarantees. Growing snapshots retain initial PCM; low-confidence snapshots shorter than two seconds wait for more evidence, while a completed speech boundary is decoded with the available audio. A 240 ms VAD pause queues an automatic-mode boundary even during active inference. Jobs drain each boundary before analyzing the next turn. Silence never triggers noise-only recognition; queues and PCM remain bounded. A switch within uninterrupted or overlapping speech may still share one language for that window.

With Chrome translation selected, preparation loads the two non-target source-to-target native translators; an explicit translation choice loads one multilingual resident worker instead. The bounded translation queue selects a pair from each source revision and preserves exact revision identity. Revisions already in the subtitle language are paired with their own text without a translation call. Speaker analysis remains asynchronous and independent; no per-speaker language lock or persistent voice/language cache is added. Ready models/pairs are reused within a prepared session and across language-only changes before capture, then released on Stop; downloaded artifacts stay cached for subsequent preparations.

See [automatic-language verification](../verification/asr/automatic-language.md) for the synthetic three-language meeting and measured limitations.

## Subtitle language and independent audio detection

The persisted `ModelOptions.targetLanguage` defaults to `ko` for old settings and selects `en`, `ja` or `ko`. Preparation freezes it with recognition/translation/detection/speaker settings. Popup cache checks, Advanced download labels, engine probe/prepare, offscreen session languages, native translator creation and worker requests use the same target. Automatic sessions prepare only the other two source-language pairs. Overlay validation accepts the three supported targets; exact source/revision pairing and caption lifecycle are unchanged. A source bypasses the translator only when it matches the selected target.

`languageDetection=voxlingua` prepares a separate bounded WASM worker running the pinned Apache-2.0 VoxLingua107 ECAPA-TDNN ONNX graph. It consumes copied 16 kHz PCM without modifying recognition input, performs one forward pass and normalizes the three supported language logits. The pinned label map identifies English/Japanese/Korean at indices 20/45/51. Recognition receives that fixed language, and confidence flows through the existing uncertain-snapshot policy. Stop, pagehide, navigation and disposal terminate the detector and reject late replies. Manual source selection never prepares it. Detector failure is visible and never falls back to shared detection. General text decision models such as Laya cannot replace audio detection before transcription.

`languageDetection=whisper` retains shared encoder detection, with recent-language tie breaking. The separate classifier may classify language faster but still adds work before ASR; total recognition and caption delay must be measured separately. `speaker=off` skips WeSpeaker preparation and embedding work. An explicit WeSpeaker selection that fails preparation fails visibly; the old implicit default retains its existing optional-speaker behavior.

The dev launcher registers its required TranslateKit pairs and SODA language packs in its owned profile before Chrome startup and waits up to 180 seconds for Chrome's first page, covering the 120-second component-download budget. It preserves unrelated profile state and cached files.

The supported recognition picker contains Chrome defaults, Small FP16 and Turbo FP16. The supported translation picker contains Chrome TranslateKit and Hy-MT2. Tiny/Base/Small q8 and NLLB/M2M100 remain pinned only for reproducible audits; persisted retired selections migrate independently to Chrome defaults. This is a selection migration, not runtime error fallback. See the dated model-quality audit for measured reasons and remaining errors.

Automatic Japanese output shares the English-to-Japanese native instance and translates Korean through the Korean-to-English instance first. This avoids creating two Japanese translators under one transient activation in Chrome's Korean-language profile. Intermediate English never reaches the caption channel; the visible stream remains paired with the original Korean source revision and Japanese target. Manual Korean-to-Japanese preparation uses its direct native pair. Other targets retain their existing native paths. Cache probes inspect these actual prepared pairs.


Advanced remains shared. Audio recognition/detection/speaker controls carry Audio badges, translation carries Audio+Image, and OCR carries Image. Every selector submits one `models` command containing both the shared model options and image options. The service worker stops the old audio operation, configures the image broker (retiring incompatible translation/OCR inference while retaining completed overlays), then forwards the combined snapshot to offscreen. Offscreen owns the entire sequence: stage 1 audio/translation preparation, stage 2 selected OCR file download/verification. It stays preparing through both stages and emits one ready event/notification only when both finish. Closing Advanced cannot interrupt or lose the second-stage handoff; reopening observes the common snapshot. No capture or image analysis starts during preparation.

Advanced has one preparation status, current-stage progress bar, prepare/retry and Stop group. Read-only model cache inventories remain per selector. Common Stop aborts pending OCR transfer and disposes the audio engine; retry restarts the whole operation with verified cache reuse. Generation fencing prevents late or superseded stages from announcing completion. Internal OCR preparation state/revisions remain separate from image-session results, but have no separate user-facing control surface. Actual bytes feed OCR weighted progress; cache/hash verification remains indeterminate. OCR completion means verified files, with sandbox/model initialization deferred to explicit analysis. Image analysis waits for matching active preparation with an abortable wait and otherwise remains independent of audio. The sandbox receives the exact selected detector/recognizer names with verified buffers. All OCR options use the existing official host, packaged SDK/OpenCV/ONNX runtime and upstream license notices. No cloud inference or new permissions are introduced.
