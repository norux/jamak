# Webpage image translation

Current settings behavior: all Advanced model selectors use one preparation operation, one progress/status area and common Stop/retry. The unified-preparation follow-up below supersedes historical independent OCR controls.

## Research and implementation choice

The feature translates English/Japanese image text into Korean, English or Japanese entirely on-device. It discovers the current main document's `<img>` elements or lets the user click one. Original page images are neither replaced nor repainted: OCR supplies positions, and separate DOM text labels appear above the image. Pointer drag and keyboard arrows move individual labels, including outside the image. PNG export is an explicit flattening step; its canvas expands to retain moved labels and the original pixels/crop.

| Candidate | Evidence and fit |
| --- | --- |
| Tesseract.js | Its [official FAQ](https://github.com/naptha/tesseract.js/blob/master/docs/faq.md#is-handwritten-text-supported) explicitly excludes normal handwriting. Small/established, but a poor match for the handwriting request. |
| PP-OCRv5 | [Official recognition documentation](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/text_recognition.en.md) describes English/Japanese, handwriting and vertical text support. The [official browser SDK](https://github.com/PaddlePaddle/PaddleOCR/tree/main/paddleocr-js) returns quadrilaterals, line text and model scores. Chosen for real local browser execution and spatial labels; upstream capability is not a guarantee on arbitrary handwriting. |
| TrOCR handwritten | [The model card](https://huggingface.co/microsoft/trocr-base-handwritten) targets single text-line images, requiring a separate detector/cropping stage for full images. Worth evaluating for difficult English cursive, but not a demonstrated multilingual replacement in this change. |
| Small vision-language models | [Qwen3.5-0.8B's ONNX card](https://huggingface.co/onnx-community/Qwen3.5-0.8B-ONNX) describes browser-compatible multimodal inference but positions this small model for prototyping/research. It does not establish reliable OCR coordinates or handwriting quality here. No VLM or cloud fallback is shipped. |

The default uses official PP-OCRv5 **mobile** detection/recognition with `@paddleocr/paddleocr-js` 0.4.2 and its locked ONNX Runtime Web 1.30.0, WASM/CPU, single thread. Downloads total **21,544,960 bytes**, plus the selected translator's existing artifacts or Chrome's separate TranslateKit language packs. Models are reused in Cache Storage, but loaded readiness is not inferred from a cached flag. Every archive is checked for its exact size and SHA-256 on download/cache read.

Official archive base: `https://paddle-model-ecology.bj.bcebos.com/paddlex/official_inference_model/paddle3.0.0/`.

Paddle's archive host returned no CORS header in actual Chrome. A host permission limited to that download domain permits the data fetch; no wildcard website host permission is used. Model buffers are passed into a packaged, opaque-origin sandbox via MessageChannel. Only that sandbox permits OpenCV's generated dynamic bindings; it has no Chrome APIs or parent DOM access. Its CSP allows packaged/data runtime assets, with no external connections. Code, OpenCV and WASM ship inside the extension. Apache-2.0, ONNX Runtime MIT, Clipper Boost, YAML MIT and argparse Python-2.0 notices/licenses ship in `apps/chrome/public/licenses/` and the built extension's `licenses/` directory.

## Background workflow and source-language detection

1. Open Jamak’s visible **오디오 / 이미지** tabs and choose **이미지**. Select the ko/en/ja output, then **탭의 모든 이미지 번역** or **이미지 선택해서 번역**. The popup closes; no analysis tab/window opens. Escape cancels image selection.
2. The existing single offscreen document runs the independent image job after popup closure. Automatic mode snapshots the displayed main-document `<img>` list and processes it serially. New analysis retires old results. Image actions do not prepare, capture or stop audio. The Advanced translation choice and shared `targetLanguage` preference are frozen per operation, preserving recognition/detector/speaker fields.
3. Clean image pixels keep the full image at up to 2560px on their longest side. Other images use an action-authorized visible screenshot crop. Keep the source tab active for that capture. Cropping/occlusion can lose content; CSS backgrounds, iframes and later additions are excluded. Initial scroll position is restored after completion/Stop.
4. OCR provides text/quadrilaterals. The service worker invokes [Chrome’s local text-language classifier](https://developer.chrome.com/docs/extensions/reference/api/i18n#method-detectLanguage) on each line and its image context. Reliable en/ja/ko results are used; unreliable lines borrow only a unique, script-compatible, reliable image language (at least 20% context share, with no major unsupported-language share). Unknown/unsupported text is not guessed. Mixed English/Japanese images retain each line’s own language. This classifies recognized text, not the image’s visual appearance; Korean OCR quality remains unestablished.
5. Translate each detected source to the selected target through main’s native/model translator API. Same-language/numeric regions skip inference. Native auto pairs prepare directly from the popup action before OCR for first-use pack activation; Hy-MT2 loads lazily for differing text. Valid cached weights are reused, while memory/GPU loading remains preparation. Native packs can still require a first download.
6. Separate page labels appear after completed regions, preserving the original image. Drag or focus and use arrows (Shift: 10px). **원문 · 번역 수정** corrects OCR, source language or translation inline. **PNG 저장** flattens current labels with original pixels, expanding margins for positions outside the image. A new target/analysis starts a new job; OCR reuse across separate analyses is not promised.
7. Stop aborts inference/downloads, removes the sandbox and retains completed results for movement/direct translation editing/export. Source retranslation after Stop needs a new analysis. The draggable download/eye pair provides export and independent caption visibility; correction opens only from each caption’s pencil. Visibility persists through newer paints. The popup can be moved by its header; outside clicks/caption dragging, explicit close or Escape dismiss it. Five native radio font-size presets update the selected region and PNG without inference. Moved captions offer original-position reset without reanalysis. Source replacement/navigation rejects obsolete paint. Session state can be restored from offscreen memory after worker suspension; tokens, document IDs and revisions reject old replies. Navigation/tab closure/new analysis clears prior result memory. Pixels and text are never persisted or sent for external inference.

The quality workspace was consulted directly through Orca. Its PR #2 was merged as `3df965d4138b23f7bed0cb3dbea94798a2ce4fdc`; this branch fast-forwarded to that main before reapplying the isolated image feature. Common model options, native/model translators, worker contracts and quality’s model pruning were retained from main. Audio target languages, VoxLingua/speaker choices and warm translator preparation are therefore not replaced by an older image branch implementation.

Quality recommended `chrome.i18n.detectLanguage` for OCR text: no model download/preparation or first-use gesture is needed. Offscreen supports only the runtime extension API, so CLD and capture are brokered in the service worker. VoxLingua is audio-only, and Laya/Kev/OpenJev were not established as better OCR classifiers. A separate decision model would add unnecessary model/runtime cost here. [Chrome’s AI LanguageDetector API](https://developer.chrome.com/docs/ai/language-detection) was considered, but its additional initial availability/download/user-activation handling is unnecessary for this limited classifier.

An actual Chrome probe returned a reliable en/ja/ko decision on full sentences in ~0.1–0.4ms. Isolated `Hello world`, `明日`, `駅` and `OK` were unreliable, sometimes naming an unrelated language. A mixed image returned ja63%/en36%; both lines now receive their own supported source using per-line results/context. These are local observations, not a latency or classifier-accuracy guarantee. Inline source correction remains available.

## Handwriting evidence and remaining errors

Real English cursive was tested separately from printed text using the public IAM line linked by the [TrOCR model card](https://huggingface.co/microsoft/trocr-base-handwritten). The image/weights remain ignored under `.ralph/image-models`, not committed or distributed as a project fixture. Its original public image host had an expired certificate; the research-only sample was retrieved separately, without changing product TLS validation. The HF OCR fixture's single-word crop was also inspected.

The mobile model recognized the full line as `industre".Bommented icily.letushavea` (score ~0.68), losing the name “Mr. Brown”, parts of “commented” and spacing. The larger official `PP-OCRv5_server_rec` archive (84,674,560 bytes; SHA-256 `67af91d7ab16288116d578c8055d1d4d114c8380d8059ad3c044cd52cae206f1`) was compared through the actual Chrome sandbox, downloading from the real permitted model host. It produced `induste.mteily` (~0.57) on that line. Bigger was not better on this sample, so it is **not** shipped. The tight single-word crop was missed without padding and remained misspelled with padding. These are real failures, not successful handwriting-quality evidence.

Handwriting is therefore experimental. This change does not establish Japanese handwriting, rotated/vertical text quality, general conversational translation completeness, a latency bound or a representative handwriting accuracy rate. No silent external inference or alternative model fallback hides these errors. A specialized handwritten-line model and representative English/Japanese samples would be the next quality evaluation.
