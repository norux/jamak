# Advanced local model selection — 2026-10-10

Advanced is a separate extension window with independent recognition and translation selectors. Both default to Chrome. Choices persist across reopening; changing either selection stops the old session, prepares/downloads the selected models immediately in offscreen, and retains completed cache files. Users return to the original tab and press Start after readiness. No selector initiates capture. Stop cancels preparation; reset restores both Chrome defaults.

Advanced now shows separate download labels for the selected recognition and translation models, including partial caches, Chrome pack availability and completed local files. The background stage's progress is shown while preparing. Downloaded files are not labeled as loaded models; overall readiness appears separately. The download Stop button is enabled during preparation. Successful Advanced preparation sends one local Chrome desktop notification even if the window is closed; Stop, failed/stale preparation and automatic popup preparation do not notify. Chrome/OS notification settings control visible delivery.

Selection is saved before preparation, including on preparation failure. Old model metadata without settings is accepted only for Chrome defaults, so it cannot show SODA or enable Start for an explicit Whisper selection. The popup regression first failed with stale SODA metadata after selecting Tiny/M2M100; the corrected popup shows the new selections and disables stale readiness.

## Registered choices

- Recognition: Chrome SODA (Turbo fallback for automatic/Korean/unsupported API), Whisper Tiny/Base/Small q8 on WASM, Small FP16 and Large v3 Turbo FP16 on WebGPU. These are official Whisper family names; Pro/Flash are not names in the [official Whisper model list](https://github.com/openai/whisper).
- Translation: Chrome TranslateKit, [Hy-MT2 1.8B](https://huggingface.co/tencent/Hy-MT2-1.8B) q4f16 (~1.38 GB) on WebGPU/FP16, and [NLLB-200 Distilled 600M](https://huggingface.co/Xenova/nllb-200-distilled-600M) q8 / [M2M100 418M](https://huggingface.co/Xenova/m2m100_418M) q8 on WASM/CPU. Hy-MT2 is Apache-2.0; NLLB's upstream CC-BY-NC-4.0 restriction is displayed in Advanced; M2M100 is MIT. All execution is local; there are no API/cloud model choices.

Every model uses pinned repository revisions and exact artifact sizes; large artifacts have SHA-256 checks on download. Runtime loading reads prepared cache only. Explicit choices do not silently fall back to another model. Automatic mode routes each recognized language to the selected translator; Korean continues to bypass translation.

## WebGPU translation and streamed revisions — 2026-10-10

Hy-MT2 is an optional comparison model; Chrome remains the default. Its community q4f16 conversion is pinned to `cb415aec769544c3f9cefdc312142b592e731bb9`, with complete inventory (1,383,140,565 bytes) and SHA-256 validation of its embedded-weight ONNX file. Download labels, popup readiness and worker loading use the selected dtype. Preparation checks WebGPU FP16 before downloading. The locked runtime requires bundled asyncify for WebGPU; jsep remains the WASM runtime. The conversion's inherited external-data setting is disabled because its weights are embedded. Tencent's upstream Apache-2.0 license and attribution remain separate from the application license.

Chrome streams cumulative phrase text when supported, preserving its Japanese phrase splitting and complete-result compatibility path. Hy-MT2 uses TextStreamer with explicit English/Japanese to Korean prompting and deterministic decoding. The host buffers only the latest cumulative chunk. Intermediate revisions are provisional even for a finalized source; generation completion is final for that exact source revision, while caption completion also requires final recognition. Unchanged same-language source final confirmations reuse the completed translation, including confirmations queued during generation. Corrections reset translation completion, retain revision watermarks and reject old-source chunks. Stop cancels native readers or terminates model workers. The existing overlay uses its 180 ms cadence, previous-pair retention and measured reading progress. Korean continues to bypass every translator.

### Korean updates during ongoing speech

The requirement is visible Korean correction while the speaker is still talking. Token generation alone did not satisfy it: advancing the published source on every ASR draft rejected slower Hy-MT2 chunks and delayed the first Korean display to ~8.6 s. A failing queue regression reproduced this starvation. Streaming translators now validate incoming recognition separately, pin the active published source, and coalesce newer same-language corrections for the next translation. This keeps source/translation pairing exact while allowing current Korean chunks to paint. Language changes retire the pinned source immediately; Korean bypass shares the queue's published translation sequence so generated chunks cannot block it with a higher watermark. A separate failing regression covered Japanese → Korean → Japanese corrections while the old stream was still active.

The real conversation check now requires at least two different visible Korean texts in one caption before the first fixture turn ends, measured with the audio playback clock. It records wall-clock source/translation revisions and media-clock overlay frames, so delaying a published final cannot fake success.
